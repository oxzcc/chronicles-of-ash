# Хроники Пепла — правила проекта

Браузерная онлайн-игра: ИИ-мастер ведёт на русском приключение, игрок пишет что угодно, исход решают кубики. Миров несколько: «Хроники Пепла» (тёмное фэнтези в духе Baldur's Gate 3) и, в работе, «Таинственные дела в Аркхэме» (детектив по мотивам Лавкрафта, первая половина XX века).
План разработки: https://claude.ai/artifact/UoNhXiCoax1SB3WPNLV3JD (фазы 0–5, ключевые решения, риски). Перед задачей сверяйся с фазой, к которой она относится.

## Главный принцип

**Числа считает код, слова пишет ИИ.** Броски, HP, золото, предметы, враги, переходы по карте — только в `packages/engine` на сервере. Модель лишь *предлагает* изменения в JSON, движок применяет их с ограничениями (`applyChanges`, `normalizeEnemies`). Клиент не видит ключей и не может подменить состояние.

## Стек

- pnpm workspaces, Node 22, TypeScript (strict, `noUncheckedIndexedAccess`)
- `apps/web` — Next.js 16 (App Router): интерфейс и API-ручки, стриминг через SSE
- `packages/engine` — правила (упрощённая D&D 5e): кубики, персонаж, проверки, бой, карта, лимиты изменений. Без зависимостей, работает и в браузере. О мирах не знает: расы, классы, навыки и типы мест получает параметром `Ruleset`
- `packages/worlds` — миры: `src/<id>/` — правила (`rules.ts`), стиль картинок (`art.ts`), куски промптов и запасной квест (`index.ts`), описание мира (`world.md`, идёт в кэшируемую часть промпта) и визуальный стиль (`style.md`). Реестр — `src/index.ts`; мир героя — `worldOf(character)`
- `packages/llm` — слой моделей: OpenRouter (стриминг, tool calls, учёт стоимости), маршрутизатор по роли/тарифу, промпты, JSON-контракт ответа (zod), цикл хода с `roll_check`, фейковая модель
- `packages/db` — PostgreSQL + Drizzle ORM (схема, миграции в `packages/db/migrations`)
- `packages/images` — картинки: FLUX через fal (`sync_mode`), вырезание фона BiRefNet, постобработка sharp, стилевые промпты, описания для FLUX служебной моделью, локальное хранилище, фейковый генератор
- `packages/game/src/visuals.ts` — очередь картинок в таблице `images` (FOR UPDATE SKIP LOCKED), карточки NPC, библиотека фонов по типу локации; воркер стартует в `apps/web/instrumentation.ts`
- `tools/` — `check-apis.ts` и арена слепого сравнения моделей (`tools/arena`)

## Команды

```bash
pnpm install
pnpm db:up              # PostgreSQL + Redis в Docker
pnpm db:migrate         # применить миграции
pnpm dev                # http://localhost:3000 — стенд одного хода
pnpm test               # vitest по всем пакетам
pnpm typecheck          # tsc по всем пакетам и tools
pnpm build              # сборка Next.js
pnpm check:apis         # доступ к OpenRouter и fal.ai (--images — пробная картинка)
pnpm arena:run -- <model> <model> …   # 10 тестовых сцен на моделях (фэнтези)
pnpm arena:run -- --world arkham <model> …   # 9 сцен мира Аркхэма (на запасном деле)
pnpm arena:ballot <файл прогона>      # анонимный бюллетень для оценки
pnpm lora:dataset -- --world arkham   # датасет LoRA стиля: data/lora/<мир>/ + подписи → zip
pnpm lora:train -- --world arkham     # обучить LoRA на fal (спросит подтверждение)
pnpm lora:compare -- --world arkham   # картинки с LoRA и без → data/lora/compare/…/index.html
pnpm images:restyle -- --world arkham # перерисовать готовые картинки мира в нынешнем стиле (спросит подтверждение)
```

Схема БД меняется так: правка `packages/db/src/schema.ts` → `pnpm --filter @ash/db generate` → проверить SQL в `migrations/` → `pnpm db:migrate`.

## Соглашения

- Одна задача — одна ветка (`phase-N/кратко`) и один pull request с описанием и тестами. Сливать только после «ок» владельца.
- Тексты для игрока и промпты — по-русски. Код, идентификаторы и коммиты — по-английски; комментарии можно по-русски.
- Импорты внутри пакетов без расширений (`./dice`), между пакетами — `@ash/<пакет>`.
- Любая случайность — через `Rng` из движка: `secureRng` на сервере, `mulberry32(seed)` в тестах и раскладке.
- Всё, что зависит от мира (названия, валюта, жанр, стиль, типы мест), — в `packages/worlds`, а не в ядре. Новый мир: папка `src/<id>/` по образцу `fantasy`, запись в `WORLDS`; `worlds.test.ts` проверит его данные. Лист героя хранит `world`; листы без него — фэнтези.
- Дело (мир с `features.case`): разгадка, ответы и ненайденные улики живут только на сервере. Клиенту кампания уходит через `publicCampaign` — в любой новой ручке, которая отдаёт кампанию, тоже. Улики и адреса мастер только предлагает (`clues`, `reveal`), движок проверяет место и лимиты; очки за дело считает `closeCase`, служебная модель лишь ставит вердикты.
- Рассудок (мир с `rules.sanity`): мастер предлагает `changes.sanity`, движок режет (−4…+1 за ход); на нуле — срыв (`breakDown`), на трети и меньше герой «на грани» (меньше вариантов, мрачнее развязка). Потеря в деле стоит очков.
- Правка кусков промпта мира (`gm` в `src/<id>/index.ts`) → поднять `gm.version` этого мира и прогнать арену с `--world <id>`.
- Изменение промпта мастера → поднять `PROMPT_VERSION` в `packages/llm/src/prompts/gm.ts` и прогнать `pnpm arena:run -- --scenes …` на текущих моделях.
- Находки хода игрок видит подсветкой в тексте реплики, прямо пока мастер пишет: мастер помечает слова (`finds` у реплики), `previewMarks` в `packages/game/src/marks.ts` на лету оставляет только то, что движок примет (те же проверки), а `resolveMarks` после хода — только принятое по `TurnEffect`; принятая находка без пометки получает ярлык в конце реплики. Помеченные улики и адреса идут в проверку вместе с `clues` и `reveal`. Клик по находке ведёт к улике в досье, к адресу в справочнике, к листу героя. Новое изменение состояния героя или дела → своя плашка (`packages/engine/src/effects.ts`) + тест.
- Память о людях (`memory` в кампании, `packages/engine/src/npcs.ts`): мастер предлагает `npcs` (манера речи, сдвиг отношения −1…+1, что человек сообщил), движок пишет только о тех, кто говорил в этом ответе, держит отношение в −2…+2 и показания (до 6) — это и есть показания в досье. Карточки собеседника и названных людей идут в сцену (`peopleCards`).
- Жители дела: мотив, алиби, секрет и ложь (`lie.breaks` — улика, которая её опровергает) — только у мастера, `publicCampaign` их вырезает. Поворот (`twist`) наступает, когда найдена половина ключевых улик (`checkTwist`), и только тогда попадает в сцену.
- «Предъявить» — свой ход (`present`): уличает ли улика собеседника, решает `presentClue` (своя улика, один раз), мастер лишь описывает признание. Вариант с `present` игра оставляет, только если улика уже найдена.
- Новое поле в ответе модели → zod-схема в `packages/llm/src/schema.ts` (снисходительная, с `.catch`) + лимит в движке + тест.
- Модели не зашиваются в код: только через переменные окружения (`NARRATOR_MODEL_*`, `UTILITY_MODEL`, `VISION_MODEL`).
- Ключи и пароли — только в `.env` / переменных окружения сервера. Никогда в коде, коммитах и чате.
- Без ключа OpenRouter всё работает на `FakeProvider`, без ключа fal — на `FakeImageProvider`: интерфейс разрабатывается без трат.
- Создание кампании отдаёт поток (SSE): события `progress` для полосы загрузки, затем `done`. Прогресс настоящий — по объёму скрытых рассуждений и разделам JSON; ожидаемые объёмы и время — в `EXPECT` в `packages/game/src/progress.ts`, при смене модели рассказчика поправить.
- Ранний старт: дело начинает придумываться, пока игрок рисует портрет (`/api/campaigns/pregen`, `PregenStore` в `packages/game/src/pregen.ts`); старт берёт заготовку, только если герой не изменился (`draftKey`). Хранится в памяти процесса — в фазе 4 перенести в Redis. Cookie игрока выдаёт `apps/web/proxy.ts`.
- Облик людей на портретах выбирает код, служебная модель лишь вписывает: телосложение, причёска и цвет волос, приметы (только зажившие), слой под верхней одеждой (`{under}` в наряде, `underlayersEn` мира: у героини не больше одного открытого из четырёх, у NPC — по имени), у героя ещё возраст, наряд, поза и выражение. Поза — одно действие для обеих рук вместе с предметом, предмет в наряде — «with …» без глагола: иначе FLUX дорисовывает третью руку. Готовый портрет проверяет `VISION_MODEL` (руки, размер головы) — `packages/images/src/inspect.ts`.
- Картинки никогда не задерживают ход: текст идёт сразу, картинки — из очереди; клиент показывает силуэт и опрашивает `/api/campaigns/:id/scene`.
- LoRA стиля мира: триггер и короткий префикс — в `art.lora` мира, веса и сила — только в окружении (`FAL_LORA_<ID>_URL`, `FAL_LORA_<ID>_SCALE`). Датасеты — в `data/lora/` (не в git). LoRA рисуется той же моделью, на которой обучена (сейчас klein 9B **Base**). Сменили LoRA, силу или промпты картинок — `pnpm images:restyle`, иначе старые фоны и портреты останутся в библиотеке.
- Готовые картинки лежат в `data/images/` (в git не попадают); в фазе 4 — S3 + CDN за тем же интерфейсом `ImageStorage`.
